# ADR-030: `cpu-a9`, a native ARMv7-A interpreter (integer, A32), validated against QEMU

Status: **Accepted** (milestone P5, optional, partial: integer A32 only). Date: 2026-10-17.

## Context

Spec §6 phase 3 and §15 P5 call for a native PS engine. The first slice is the core: an ARMv7-A
instruction-set simulator that runs the bare-metal Rust firmware of this repository without
Xilinx QEMU. `mem-sys`, `ps-periph` and the GIC are other engineers' crates and build against the
`ps_bus::Bus` trait, which this crate only uses.

## Decision

* `crates/cpu-a9`: pure Rust, `#![forbid(unsafe_code)]`, depends only on `ps-bus`.
* One `Cpu::step(&mut dyn Bus) -> StepResult` executes one A32 instruction and returns
  `Executed { pc, cycles: 1, event }` or `Unimplemented { pc, insn }`. An unimplemented
  encoding never changes state and never runs as something else. The caller decides what to do.
* Banked registers for User/System, FIQ, IRQ, Supervisor, Abort and Undefined. CPSR NZCVQ, GE,
  A, I, F, T and mode. Thumb (T=1) is executed by `thumb.rs` (see the Thumb section below).
* Exceptions follow the ARM ARM: LR and SPSR per mode, I (and F for FIQ) set on entry, vectors at
  VBAR or 0xFFFF0000 with SCTLR.V. The IRQ and FIQ lines are sampled between instructions.
* WFI and WFE wait without advancing the PC until an interrupt line, or `send_event`, wakes them;
  the wait reports `Event::Idle`.
* CP15 is modelled for the registers the firmware and the BSP touch. Cache and TLB maintenance
  operations are no-ops (caches are not modelled). Unknown CP15 encodings are `Unimplemented`.
* No MMU. Physical = virtual through the `Translate` trait; `Identity` is the default. Setting
  SCTLR.M makes the next step `Unimplemented`, so the core never runs untranslated by accident.
* Unaligned loads and stores are split into bytes (ARMv7 behaviour with SCTLR.A clear); with
  SCTLR.A set they are alignment faults. Exclusive monitor: one local address, cleared by any
  exception entry, CLREX and STREX.
* `UDIV` and `SDIV` are undefined (the Cortex-A9 has no integer divide). They take the undefined
  instruction exception. `assembler -march=armv7-a` rejects them, which confirms the encoding
  is not in the baseline ISA.

### Not decided here

VFP and NEON, the MMU and TLB walk, the GIC, timers, SCU, caches and the peripherals are
out of this crate. Each is either `Unimplemented` at the core or lives in another crate.

## Result for each Rust firmware image

The 31 images `fixtures/elf/rust_*.elf` are loaded at their link addresses (RAM 0x00100000,
stack top 0x00500000), with a stub UART1 that records TX FIFO writes at 0xE0001030, read-as-zero
device windows and a step budget of 5 000 000. Reproduce with
`cargo test -p cpu-a9 --test rust_firmware every_rust -- --nocapture` (the `RUSTFW` lines).

Common to all 31: **no image needs Thumb** (all A32), **none needs VFP** (soft-float ABI, no VFP
instruction in any image), **none needs the MMU** (SCTLR stays 0x00C50078), and **no image hits an
unimplemented instruction in its run**. Every distinct instruction word of the 31 images
(11 423 words, `tests/data/rust_firmware_insn_words.txt`) decodes to an implemented class.

"Runs" means the image reaches its own end (all PASS lines, or its end-of-test write), with the
device model it needs absent.

## Differential test against QEMU

`crates/cli/tests/cpu_a9_diff.rs` runs `examples/rust-hello` through `zynqsim run` on the Xilinx
QEMU and `rust_hello.elf` on the interpreter, and compares the UART text. Both print the same
three lines (`hello from Rust on the simulated Cortex-A9`, `sum(1..=100) = 5050`,
`RESULT: ALL PASS`). The test skips with `SKIPPED:` when QEMU is absent.

This is a text comparison of one image. It is not an instruction-by-instruction differential
test: that needs QEMU's gdb stub to step the CPU, which the PS adapter does not drive yet. Listed
as a limit in TESTPLAN.

## Consequences

* The interpreter can run the rust-hello firmware with no QEMU. The other 30 images need the
  peripheral, GIC and timer models before they can finish; the native engine is not yet a
  replacement for QEMU on the regression.
* Unimplemented instructions are visible to the caller at the first instruction that needs them,
  never run silently wrong. The stub list above is the to-do list for the rest of P5.
* Flags are checked against an independent reference for all 16 opcodes. The reference is written
  in i64/u64 arithmetic, so it does not share code with the interpreter's `AddWithCarry`.

## Thumb and Thumb-2 (`thumb.rs`)

The T32 decode is in `thumb.rs`; the shared semantics are the A32 ones: the barrel shifter and
add-with-carry (`alu.rs`), loads and stores with alignment splitting (`mem.rs`), exception entry
and banking (`state.rs`), CP15 (`cp15.rs`), the MSR field writer. What is Thumb-specific: R15 reads
as the instruction address + 4; an ALU write to PC clears only bit 0 (no interworking), while a
load into PC (LDR, LDM, POP) interworks as BX; 16-bit data processing sets flags only outside an
IT block; ITSTATE advances before each instruction (so an exception taken by it saves the next
state) and is cleared on exception entry; the Thumb-2 DP modified-immediate uses ThumbExpandImm.
The 32-bit DP core is the same table as the A32 one (`t_dp_core`); the property tests check each
class against its A32 twin. Unallocated encodings return `Unimplemented`. UDIV and SDIV raise the
undefined exception, as on the Cortex-A9. Not decoded: the parallel ops, SXTB16/UXTB16, the
SMLAD family, SMULWy in T32, LDRT/STRT and coprocessor 10/11 in Thumb; these are reported.

## Alternatives considered

* Thumb in the same step: rejected for this slice. The firmware is all A32, and Thumb doubles the
  decoder. It is a stub with a reported `Unimplemented`.
* Using the `object` crate to load the ELF: rejected. The loader is 20 lines and a dev-dependency
  would add a crate for test use only.
* Assembling the test programs at test time: rejected. The words are generated once from the
  Xilinx toolchain and committed with their source text in comments, so the tests need no tools.
