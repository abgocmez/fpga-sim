# ADR-038: `ps7_init` replay and PS clock tree derivation

Status: **Accepted** (Milestone Task A; Windows, Linux, macOS). Date: 2026-10-19.

## Context

Vivado hardware handoffs (`.xsa`) include `ps7_init.tcl` (along with `ps7_init.c` and `.h`), defining the hardware initialization sequences generated by Vivado for the processing system. This includes PLL configurations, clock dividers, MIO pin muxing, DDR controller settings, and peripheral enables.

Previously, ZynqSim only inventoried `ps7_init` files as names in the archive metadata. The simulation relied on fixed reset values or QEMU's initial state. To faithfully reflect Vivado hardware handoffs and support unmodified firmware that assumes initialization has run, ZynqSim parses `ps7_init.tcl`, replays the initialization sequence before CPU execution begins, and derives the PS clock tree.

## Facts found on this machine (checked, not assumed)

| Fact | Evidence |
|---|---|
| Vivado 2022.1 XSAs structure initialization in silicon-versioned procedures: `ps7_mio_init_data_3_0`, `ps7_pll_init_data_3_0`, `ps7_clock_init_data_3_0`, `ps7_ddr_init_data_3_0`, `ps7_peripherals_init_data_3_0`, `ps7_post_config_3_0`, totaling 213 operations in standard designs | Parsing `fixtures/handoff/design.xsa` and `fixtures/xsa/*.xsa` |
| QEMU's Remote-Port HP0 memory path decodes SLCR (`0xF8000000..=0xF8000FFF`), allowing register reads, writes, and unlock verification (`LOCKSTA` toggles from 1 to 0 on writing `0xDF0D` to `0xF8000008`) | Probe test in `crates/backend-qemu` |
| QEMU's Remote-Port HP0 path does **not** decode DDRC (`0xF8006000..=0xF8006FFF`), DEVCFG (`0xF8007000..=0xF8007FFF`), PS GPIO (`0xE000A000..=0xE000AFFF`), or CoreSight debug components (`0xF8800000..=0xF88FFFFF`), returning DECERR | Probe test in `crates/backend-qemu` |
| QEMU does not model DDRIOB DCI calibration status (`0xF8000B74` reads 0) | HP0 probe read on QEMU |
| In UG585 Chapter 10, DDR controller status register (`0x54`) bits [2:0] indicate operating mode (0x7 = normal operating mode) | UG585 and `ps7_init.tcl` polling mask `0x00000007` |
| SLCR register `0x140` is `GEM0_CLK_CTRL`, while `0x154` is `UART_CLK_CTRL` | UG585 Appendix B.28 |

## Decision

1. **Parser & Clock Tree in `crates/xsa-import/src/ps7_init.rs`**:
   - `Ps7InitOp` represents the four fundamental operations: `Write`, `MaskWrite`, `MaskPoll`, and `MaskDelay`.
   - `extract_procs` extracts procedures taking into account Tcl parameter lists and nested braces.
   - Candidate sets for 3.0, 2.0, 1.0, and unversioned silicon are evaluated in order.
   - `derive_clock_tree` extracts the PLL multipliers (ARM, DDR, IO PLLs) and clock dividers (ARM_CLK_CTRL, UART_CLK_CTRL) from the sequence to produce a `ClockTree` (PS_CLK 33.333 MHz, CPU 666.667 MHz, Periph 333.333 MHz, TTC 111.111 MHz, UART 100 MHz).

2. **Peripheral Model Updates (`crates/ps-periph`)**:
   - `Slcr`: Updated `REGS` to name `GEM0_CLK_CTRL` (0x140), `UART_CLK_CTRL` (0x154), and `DDRIOB_DCI_STATUS` (0xB74, reset `0x0000_2000`). Writes to any register in the SLCR 4 KiB range when unlocked are retained.
   - `DdrC`: Created a dedicated `DdrC` model at `0xF8006000` reporting `0x0000_0007` on status register `0x54` to satisfy DDR initialization polling.

3. **Replay Engine in `crates/sim-api/src/ps7_init.rs`**:
   - `load_project_ps7_init`: Loads `ps7_init_ops` and `clock_tree` from the project's XSA or from a local `ps7_init.tcl`.
   - `[boot] ps7_init = true|false`: Project configuration switch. Defaults to true when an XSA or `ps7_init.tcl` is available, and false otherwise, preserving existing hashes for standalone firmware.
   - `replay_native`: Applies operations directly to `SystemBus`. `MaskPoll` checks up to 2000 iterations and fails with an error naming the failing register address and mask if not satisfied.
   - `replay_qemu`: Replays operations via `QemuMachine::write_memory` and `read_memory`. Registers not decoded over Remote-Port HP0 (`qemu_skips_addr`) and DDRIOB DCI polling are explicitly skipped.

4. **Testing**:
   - Unit tests in `xsa-import` and `sim-api`.
   - CLI integration test `crates/cli/tests/ps7_init_replay.rs` verifying native replay success and negative poll timeout diagnostics.
   - `examples/vivado-handoff` verified to pass end-to-end with replay active and identical trace hash (`fnv1a64:a0040ac376267dd2`).
